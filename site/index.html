Desktop log reader · macOS, Windows, Linux

A log reader for the Laravel projects on this machine.

Laravel writes a log event as a header line, then its JSON context, then however many stack frames the exception carried. In a terminal that arrives as forty separate lines with nothing marking where one event stops. LogDeck parses the header and keeps everything under it attached, so a 47-frame trace is one row you can copy in a single click and paste into an issue intact.

Register the project folders you work in. LogDeck tails all of them and shows you the one you have selected.

§ 01Vocabulary

Six words the app uses precisely

These are the terms in the interface and in the code, and they mean the same thing in both places. The rest of the page assumes them.

Entry
One log event: the header line, its JSON context, and its stack frames. Filtering, search, counting and copying all operate on entries.
Line
One physical line of a file. Lines matter to the parser. Nothing in the interface asks you to act on one.
Break
A marker placed where the source file rotated or was truncated. Entries on either side of a break are unrelated in time.
Session record
Everything LogDeck has retained for a project since you selected it, across any number of breaks. It holds the newest 2000 entries and pages older ones back when you scroll for them.
Project
A folder you have registered, identified by its absolute path. Registration records your intent, so a folder with no storage/logs/ is still added and shown inert with the reason.
Target
The file being read inside a project right now: the newest file in the logs directory, or a specific one you have pinned.

§ 03Behaviour

What it does while you are looking at something else

Severity

Level is drawn as a three-pixel rail in the left gutter, at full height of the entry. Red deepens and saturates from error through emergency, so the worst thing on screen is the brightest thing in the gutter. Text with no parseable header gets a dashed grey rail: the file did not state a level, and a guess would read as one.

debug info notice warning error critical alert emergency

Rotation

When the file rotates at midnight, or someone runs php artisan log:clear while you are reading, LogDeck inserts a break and keeps every entry above it. The file emptying does not empty your screen.

Several projects

Every registered project is watched at once. The ones you have not selected keep two numbers — how many entries have arrived and the highest level among them — and throw the text away. That is what stops memory growing with the number of projects you register.

Search

Search runs over the raw text of each entry, collapsed context included. A hit buried in a stack trace expands that entry, reports how many matches it holds, and highlights them.

Channels

The single channel writes laravel.log; the daily channel writes laravel-YYYY-MM-DD.log and rotates. LogDeck resolves the logs directory rather than a filename, so either channel works, and so does a project using both. Pinning a specific file stops it following rotation; the file still streams.

Missing folders

Move a project folder away and it is marked offline with the reason. The watcher backs off from 300 ms toward five seconds and reattaches on its own when the path comes back. Nothing leaves the sidebar unless you remove it.

§ 04Architecture

Two processes, one repository

React renders and filters. Rust owns the registry, the watcher threads and every file read. Three decisions follow from that split and explain most of the rest of the code.

Session record

The stream is a record of what has been observed since you selected the project, not a rendering of the file's current contents. That distinction is the whole reason a truncation is survivable: there is no step where the app re-reads the file and finds it empty.

Tailing in Rust

One thread per project reads forward from a stored byte offset every 300 ms and pushes new entries to the front end over Tauri events. Nothing polls the filesystem from JavaScript. A file shorter than the stored offset is the truncation signal, which is why there is no filesystem-watcher dependency to configure or debug.

No fs plugin

Tauri's fs plugin fixes its allowed paths at compile time, and the paths here are folders you choose at runtime, so the plugin is deliberately absent. File access goes through the app's own commands instead. The full capability allowlist is dialog and clipboard-manager:allow-write-text. There is no network code in the app, so nothing it reads can leave your machine.

The builds are unsigned

macOS refuses the first launch with “unidentified developer”. Right-click the app and choose Open, or clear the quarantine flag: xattr -dr com.apple.quarantine "/Applications/LogDeck Desktop.app"

Windows shows SmartScreen; the app is behind More info → Run anyway. Signing both platforms needs paid certificates.

Build from source

# Needs Rust stable, the Tauri v2 system dependencies, and Node 24 LTS
$ git clone https://github.com/aravindpanicker/logdeck-desktop.git
$ cd logdeck-desktop
$ nvm use && npm install
$ npm run tauri build
